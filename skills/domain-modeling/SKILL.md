# Domain Modeling

Use this when names are fuzzy, terms drift, or the codebase lacks a stable glossary.

## Rules

- Read existing docs, `CONTEXT.md`, and ADRs before inventing new terms.
- Name concepts the way the team already talks about them unless there is a clear reason not to.
- If a term is missing or ambiguous, record the preferred wording in `CONTEXT.md`.
- Keep entities, modules, and user-facing language aligned.
- Update the glossary as decisions harden.
