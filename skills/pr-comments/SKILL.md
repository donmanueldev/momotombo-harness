# PR Comments

Use this when the user wants feedback on a pull request, review comments, or a summary they can paste into a PR discussion.

## Rules

- Read the diff and surrounding context before commenting.
- Separate blocking issues, non-blocking feedback, and nits.
- Keep each comment concrete and actionable.
- Reference files and line numbers when available.
- Prefer direct, professional English.
- If the change looks good, say so and call out only residual risks or test gaps.
